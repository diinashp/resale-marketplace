# Resale Marketplace

Сервер приложения для размещения и бронирования объявлений о продаже подержанных вещей. Объявления и бронирования хранятся в PostgreSQL.

## Бизнес-логика

- Новое объявление получает статус `AVAILABLE`.
- Продавец может удалить собственное доступное объявление.
- Покупатель не может забронировать собственное объявление.
- Бронирование переводит объявление в `RESERVED`, а бронирование — в `ACTIVE`.
- Отмена активного бронирования возвращает объявление в `AVAILABLE`.
- Подтверждение получения переводит объявление в `SOLD`, а бронирование — в `COMPLETED`.
- Одновременное бронирование одной вещи предотвращается транзакцией и блокировкой строки объявления.

## Swagger и API

Swagger UI: `/swagger-ui/index.html`  
OpenAPI: `/v3/api-docs`

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/listing` | Создать объявление |
| `GET` | `/api/listing/{listingId}` | Получить объявление |
| `GET` | `/api/listing?sellerId={uuid}&status={status}` | Получить объявления продавца по статусу |
| `DELETE` | `/api/listing/{listingId}?actorUserId={uuid}` | Удалить объявление |
| `POST` | `/api/reservations` | Создать бронирование |
| `POST` | `/api/reservations/{reservationId}/cancel?actorUserId={uuid}` | Отменить бронирование |
| `POST` | `/api/reservations/{reservationId}/confirm-receipt?actorUserId={uuid}` | Подтвердить получение товара |
| `GET` | `/api/reservations/{reservationId}` | Получить бронирование |
| `GET` | `/api/reservations/buyer?buyerId={uuid}` | Получить бронирования покупателя |
| `GET` | `/api/reservations/seller?sellerId={uuid}` | Получить бронирования продавца |

Входные данные и ответы передаются в JSON. Основные ответы ошибок: `400 Bad Request`, `404 Not Found`, `409 Conflict`.

## Архитектура и конфигурация

Модульный монолит на Spring Boot с единым серверным приложением. Контроллеры обрабатывают HTTP-запросы, сервисы реализуют сценарии и транзакции, сущности содержат бизнес-состояние, интерфейсы репозиториев отделяют сценарии от JPA-адаптеров и PostgreSQL. DTO определяют форматы API, мапперы преобразуют сущности в ответы.

Liquibase управляет схемой базы миграциями в `server/src/main/resources/db/changelog`. Docker Compose запускает приложение и PostgreSQL. Пароль базы задаётся переменной `POSTGRES_PASSWORD`; локальный файл `server/.env` исключён из Git.

## Запуск

Из каталога `server`: `docker compose up --build`.

## Тесты

- Unit-тесты проверяют бизнес-правила сущностей и сервисов.
- Интеграционные тесты проверяют HTTP API, Spring, JPA и PostgreSQL через Testcontainers.
- Интеграционные тесты проверяют, что при двух одновременных запросах на одну вещь создаётся только одно бронирование.
